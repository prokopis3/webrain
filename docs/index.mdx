# Give your AI agent a real browser.

**Webrain is an open-source Rust CLI and MCP server for browser automation and web scraping.** Install one binary, connect an MCP-capable client, and let your agent navigate pages, inspect browser state, interact with websites, crawl URLs, and extract structured data.

The public MCP surface exposes **19 intent-based tools**. Webrain can drive Chrome, Obscura, and Lightpanda through CDP, or use browserless HTTP for static pages.

## Why use Webrain?

Most browser automation libraries give your application browser primitives. Webrain packages an agent-facing workflow around them: an MCP server, an intent-based tool surface, a built-in decision guide, structured extraction, and a cross-platform CLI.

  <Card title="One Rust binary" icon="terminal">

  <Card title="MCP-native" icon="workflow">

## Install and run

Choose your operating system to install the Webrain binary.

<Tabs>
  <Tab title="Linux and macOS">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/prokopis3/webrain/main/scripts/install.sh | bash
    ```
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    irm https://raw.githubusercontent.com/prokopis3/webrain/main/scripts/install.ps1 | iex
    ```
  </Tab>
</Tabs>

Then install the default Chrome for Testing engine, verify the environment, and start the MCP server:

```bash
webrain install
webrain doctor
webrain mcp
```

By default, `webrain mcp` uses stdio for local MCP clients. To expose the HTTP transport instead:

```bash
webrain mcp --http 9223
```

Continue with the [Quickstart](/quickstart) for client configuration, or choose a walkthrough for [Claude](/mcp/claude), [Cursor](/mcp/cursor), or [GitHub Copilot](/mcp/copilot).

## Choose the right browser

The engines are not interchangeable. Pick the one that matches the page and the operation.

| Execution path | Use it for | Important limitation |
| --- | --- | --- |
| **Chrome for Testing** | Full rendering, interactive SPAs, forms, authenticated sessions, and real screenshots | Heavier than the lightweight engines. |
| **Obscura** | Supported JavaScript pages and parallel batch work | Not a substitute for Chrome on interactive challenges or complex UI widgets. |
| **Lightpanda** | Lightweight page access and accessibility or semantic-tree inspection | No full layout and paint engine. |
| **Browserless HTTP** | Static HTML with no JavaScript or login requirement | Does not execute page JavaScript or render a browser. |

Read [Browser Engines](/concepts/browsers) for the capability matrix and [the Agent Decision Guide](/guides/agent-decision-guide) for routing rules.

<Note>
  A detected challenge is not proof that Webrain can automatically pass it. Protected pages may need a real Chrome profile with an authenticated session, and interactive CAPTCHA, consent, or two-factor steps can still require a human. Webrain reports challenge state so an agent can stop instead of silently scraping the wrong page.
</Note>

## Reproducible performance, not marketing numbers

Webrain's performance documentation separates measurements made by this project from figures published by browser-engine vendors. It records test conditions, commands, observed limitations, and the workloads where a particular engine is appropriate.

Read the [performance notes](/comparisons/performance) before comparing engines or estimating throughput. Your results will depend on the target website, hardware, browser engine, network, and concurrency settings.

## Local execution and model-provider boundaries

Webrain runs its CLI, MCP server, browser processes, and local browser profiles on the machine where you launch it. When you use `webrain chat`, prompts and model requests are sent to the model provider configured by you. A local browser does not mean that a remote model API receives no data. Review your provider's data policy before using sensitive pages.
