# CLI Reference

Drive webrain by hand — every engine has a CLI twin, and `webrain tool` reaches the
whole MCP surface when you want no model in the loop.

## Help

`webrain --help` lists every command plus **every environment variable the
binary reads**, grouped (attach/engines, stealth, network, MCP transport, vault,
SERP tiers, agent, local AI, logging). The defaults and the long explanations
live in [Environment Variables](/reference/environment); `webrain help env`
prints just that section and `webrain <command> --help` prints one command's
page.

Help follows the command path, so the deeper commands have their own page
rather than a paragraph on their parent's:

```bash
webrain install --help         # the install page + SUBCOMMANDS
webrain install watch --help   # ffmpeg/yt-dlp/whisper bundle, its own flags
webrain vault rm --help        # one vault action
webrain help install copilot   # `webrain help <cmd> [<sub>]` works too
```

`SUBCOMMANDS` is derived from the same table the overview is, so a parent page
cannot advertise a subcommand that has no page. A path that names nothing is
answered by its nearest parent and says what missed: `webrain install chat
--help` prints the install page with `No page for install chat` under it, which
is the honest answer — `chat` is not an `install` subcommand (`copilot` and
`chat-ui` are).

## Commands

| Command | Description |
|---|---|
| `webrain mcp [--http <port>]` | Start the MCP server (stdio, or HTTP on a port) |
| `webrain install [--force] [--engine chrome\|obscura\|lightpanda\|whisper\|vision\|watch] [--stealth] [--model NAME\|ID] [--model-update]` | Download a browser engine, or the local AI stack: `watch` = ffmpeg+yt-dlp+whisper-cli+model, `whisper` = STT GGUF model, `vision` = llama-server + one local vision model (ids in the [installation guide](/installation#optional-bundles)) |
| `webrain uninstall vision [--model ID \| --all]` | Remove one installed local vision model, or all of them (also clears a legacy single-model install) |
| `webrain upgrade` | Update to the latest release |
| `webrain diff <a> <b> [--max N] [--json]` | What changed between two pages, or a page and a saved baseline. Either side is an http(s) URL or a local file; no browser. Exit 1 when they differ |
| `webrain chat "<prompt>" [--provider P] [--model ID] [--key-from VAR] [--base-url URL] [--search] [--serve [--port N]] [--max-output-tokens N] [--max-prompt-tokens N] [--timeout SECS] [--yes] [--json] [--stream\|--no-stream] [--print-config]` | One Copilot agent turn on your own model key, with webrain's own MCP tools attached (it spawns `webrain mcp` itself). `--search` grounds the turn on live web results first. `--max-prompt-tokens` overrides the context window looked up from the model's catalogue, for a model nobody publishes one for. `--serve` runs the same session behind a page at `http://127.0.0.1:8787/` (SSE event stream, approval cards, `--port N` to move it; loopback only) — the memory, agent, compaction and instruction switches live in that page's Runtime tab, not on this argv. Exit 0 completed, 1 turn failed, 2 could not start. `--print-config` resolves and prints the provider with the key redacted, offline — see [Chat](/guides/chat) |
| `webrain obscura [--port N]` | Spawn the Obscura CDP server (default 9224) |
| `webrain lightpanda [--port N]` | Spawn the Lightpanda CDP server (default 9225) |
| `webrain launch <service> <profile> [url] [--headless] [--port N]` | Spawn a stealth Chrome with a persistent per-account profile |
| `webrain login <service> <profile> [url] [--port N]` | Launch + attach for interactive login |
| `webrain cookies [--port N] [--out file]` | Export cookies |
| `webrain setcookies <file>` | Import cookies |
| `webrain vault set\|list\|user\|rm` | Manage encrypted credentials (hidden prompts) |
| `webrain fetch <url>` | Attach to `CDP_URL` and fetch |
| `webrain watch <url\|file> [--detail transcript\|efficient\|balanced] [--max-frames N] [--resolution W] [--start S] [--end E] [--out-dir D] [--no-whisper] [--stt whisper\|gemini] [--vision]` | Transcript + frames for any video (no browser); `--vision` adds text captions (cloud key or local Qwen3-VL-2B) |
| `webrain screenshot <url>` | Screenshot (single or full page) |
| `webrain spider <url> [--depth N --pages N --respect-robots --json-urls --dfs --bestfirst --keywords k1,k2 --no-same-domain --discover-only]` | Crawl |
| `webrain serp "query" [--engine duckduckgo\|bing\|google\|brave\|yahoo\|baidu\|yandex\|auto] [--limit N] [--page N] [--safe] [--region R] [--http] [--no-fallback] [--json] [--proxy URL] [--headless] [--fresh] [--pipe] [--hold]` | Structured SERP JSON (`position`/`title`/`url`/`domain`/`snippet`) — the CLI twin of `webrain_serp`. `duckduckgo`/`bing`/`yahoo`/`baidu`/`yandex`/`auto` are pure HTTP (yahoo keeps a cookie jar; baidu and yandex report a challenge page as a failure, never as `0 results`); `google` auto-launches a warm persistent-profile Chrome, `brave` uses the connected CDP engine. `--http` never touches a browser at all (no render, no guest launch, even when `CDP_URL` is set) — the mode for `--engine bing --limit 50`, which otherwise pays a Chrome launch for the same rows. `--limit` clamps 1..=100, `--page` is 0-based. `--fresh` starts a brand-new profile (forces the consent modal), `--pipe` launches it with no open debugging port, `--hold` keeps the browser open after the search. `--stealth` is accepted for compat and is a no-op |
| `webrain click <i>` / `webrain type <i> <text>` / `webrain eval <js>` | Drive the `CDP_URL` backend |
| `webrain tool [<name>] ['<json>'] [--url URL] [--raw]` | Run **any** of the 19 MCP tools from the shell — no model, no client. Bare `webrain tool` lists them; `--url` navigates first; `@file.json` passes args; base64 images in a reply are elided unless `--raw`. Exit 1 when the tool reports an error |
| `webrain read <url> [--outline] [--filter TEXT] [--max N] [--json] [--proxy URL] [--browser]` | A page as markdown. Plain HTTP by default: asks for `text/markdown` first, retries `<path>.md` / `<path>/index.md`, converts only as a last resort, and reports the nearest `llms.txt`. **`--browser` renders the page in the attached Chrome instead** and runs the same tail (`source: browser`), which is the answer for a host that answers 403 to every plain HTTP client — the error names the flag when that happens. `--outline` prints the heading tree, `--filter` one section. No model either way |
| `webrain pdf <file.pdf \| url> [--json]` | A PDF's text as markdown, with a stderr line naming the pages the text layer cannot deliver. No browser, no model |
| `webrain doctor` | Full install diagnosis — version, MCP server, CDP ports (9222/9224/9225), engine discovery, vault, `recommend` |

## Index-driven interaction

`webrain click <i>` / `webrain type <i> <text>` / `webrain eval <js>` attach to
the `CDP_URL` backend and operate on **element indices** — the same
`elements[]` array that `webrain_observe` / `webrain_navigate` return over MCP:

```bash
webrain launch <service> <profile> <url>   # real Chrome on a persistent profile
webrain click 3                            # click element #3
webrain type 5 "text"                      # type into element #5
webrain eval 'document.querySelector("#email").value'
```

Get the element list from the MCP side (`webrain_observe` `what=state` or
`what=a11y` returns `elements[]` with these indices), or run
`webrain fetch <url>` to load a page and see its element count. For CSS selectors
there is no separate verb — `webrain tool` is the way in:

```bash
webrain tool webrain_observe '{"what":"html","selector":"main"}' --url https://example.com
webrain tool webrain_extract '{"mode":"schema","base_selector":"div.product","fields":[{"name":"title","selector":"h2"},{"name":"price","selector":".price"}]}' --url <url>
webrain tool webrain_interact '{"action":"wait","selector":"div.product"}'
```

## No key, no model

Nothing below needs an LLM key, a local model, or an MCP client — it is the binary
doing the work, on an argv.

| Job | Command |
|---|---|
| Read one page (text + interactive elements) | `webrain fetch <url>` |
| Structured rows from a page (CSS schema, tables, JSON-LD, autoschema) | `webrain tool webrain_extract '{"mode":"table"}' --url <url>` |
| The JSON an app fetched, and the body of one response | `webrain tool webrain_network '{"op":"log","url":"<url>","wait_ms":3000}'` then `webrain tool webrain_network '{"op":"request","id":"<id>"}'` |
| Every link, image and video on a page | `webrain tool webrain_observe '{"what":"assets"}' --url <url>` |
| Page errors and uncaught exceptions | `webrain tool webrain_observe '{"what":"console"}'` |
| Crawl a site | `webrain spider <url> --depth 3 --pages 200` |
| Search results as JSON | `webrain serp "query" --engine bing --limit 20 --http` |
| A page as a screenshot | `webrain screenshot <url>` |
| **A docs page as markdown, cheaply** | `webrain read <url>` (add `--outline` first on a long page, `--filter <heading>` for one section) |
| **Any page as markdown, including a store that 403s HTTP** | `webrain read <url> --browser` — one verb, no selector, no model |
| A PDF as markdown | `webrain pdf <file-or-url>` |
| What changed on a page | `webrain diff <a> <b>` (exit 1 on change — cron-friendly) |
| A video's transcript + frames | `webrain watch <url-or-file>` |
| Many URLs at once | `webrain tool webrain_batch '{"op":"extract","urls":[...],"schema":{...}}'` |
| Authenticated scraping | `webrain launch`, `webrain login`, `webrain cookies`, `webrain setcookies`, `webrain vault` |

What still needs a model is judgement, not capability: choosing selectors, reading
an unstructured page, and deciding what to extract next. `webrain tool` gives the
agent-less user the same verbs an agent would call, one JSON blob at a time — and
because it delegates to `webrain_mcp::call_tool`, a tool added to the server is
reachable from the shell the same day.

## `webrain doctor`

Exit codes: **0** healthy, **2** broken. Checks the install end to end —
engines, MCP server, CDP ports, vault — and prints a
`recommend` line. The first step in any troubleshooting session. `--doctor`
is an alias flag.
