## v0.20.0

<p className="text-[#888] text-sm">2026-11-24 — batch over HTTP, a context that survives a restart, and a composer you can resize</p>

### Added

- **chat**: the composer's field resizes. A handle on its own top edge drags it taller
  (arrow keys step it too), clamped to one row and `min(420px, 55vh)` and remembered per
  browser; a corner button toggles one row ↔ 30% of the viewport, with its glyph and label
  following the state.
- **mcp**: `webrain_batch` takes a `proxy` for its browserless ops (`scrape`, `read`) —
  browser ops keep the browser's exit, set at launch or by `cdp_urls`. Omit it and each
  request rotates the `WEBRAIN_PROXIES` pool.
- **mcp**: `webrain_batch op=read` — `webrain read` for N URLs with no tab: markdown
  negotiation, `.md` retry and the nearest `llms.txt` per URL, payload in `data` with
  `source` naming what arrived. The reader itself was single-URL, so a docs crawl was N
  invocations; `read`'s payload now carries the document `title` too. The verb's selection
  applies per row (`filter`, `outline`, `max_chars`) and `query`+`top_k` bm25-prune the
  markdown each row produced — one `prune_md` shared with `op=markdown`.
- **mcp**: `webrain_batch op=scrape` — the CSS schema as a batch over plain HTTP. The
  schema used to exist in two places and only one scaled: `op=extract` runs it in a browser
  tab, while `webrain_scrape` runs it browserless for one URL, so N static pages meant N
  calls or N tabs. `op=scrape` takes the same `base_selector`+`fields` with no tab, no
  render, and reports a refused host as that row's 403 instead of an empty row. The HTTP
  path also reports the document `title` now.
- **cli**: `webrain read <url> --browser` — the one-URL markdown reader now has a
  browser transport. Plain HTTP stays the default (markdown negotiation, `.md` retry,
  nearest `llms.txt`); `--browser` renders the page in the attached Chrome and runs the
  same tail, so `--outline`, `--filter` and `--max` behave identically and `source` says
  `browser`. It is the answer for a host that refuses every plain HTTP client, and the
  HTTP error now names the flag.
- **mcp**: a `js` / `interaction` argument can be `@path/to/file.js` and runs verbatim,
  so a script with quotes, backslashes or `\s+` no longer has to be escaped into JSON
  twice; a leading `@` that names no file stays literal and fails loudly.
- **chat**: Settings → Skills lists the cross-tool tree `~/.agents/skills` beside the
  runtime's own skills, with a filter box for the long tail — and the `#` catalogue is
  built from the runtime's own descriptor list instead of four hard-coded names, so MCP
  servers, skills and agent tools appear as soon as they are enabled.
- **chat**: a context ring in the composer dock opens a session-info panel — per-category
  percentages, a dashed slot for the response reservation, and a Compact button.
- **chat**: a picture link in a reply renders as a figure with a caption instead of a
  bare URL, and local image paths are served through `/local`.

### Changed

- **chat**: below 1100 px the right rail becomes a header drawer, and the two drawers
  close each other; settings lists scroll inside their own pane and their create/add
  actions match the primary pill used elsewhere.

### Fixed

- **chat**: an attachment is readable by the agent it was attached to. Uploads went to
  `%TEMP%\webrain-chat\<conversation>\` while the file tools — ours and the `preToolUse`
  fence on the runtime's built-ins — resolve against the directory the chat was started in,
  so the prompt named a path and the model answered *"outside the directory this session is
  allowed to read"*. They now land in `.webrain\attachments\<conversation>\` beside the
  tool-output spill (already gitignored), with `WEBRAIN_CHAT_FILES` for another directory and
  temp only as the read-only fallback; files uploaded before the move are still served.
- **chat**: history search is a dialog now, not a rail field. Filtering the rail in place
  pushed the matches below the fold on a long history; `Ctrl/⌘+K` (or the first keystroke
  in the rail box) opens the model picker's shell with the results in the middle, `↵` opens
  the selected row, `esc` closes, and the matched words are bolded in the theme's accent.
- **chat**: history search matches a query **word by word**. One `LIKE '%whole query%'` only
  found the words adjacent and in order, so `fpv sale` missed *fpv drone for sale*. Each
  word is matched on its own and the rows are ranked — more words hit first, then a hit in
  the thread's title message, then the phrase intact, then recency. `↑`/`↓` walk the
  results (hover moves the same selection), `↵` opens the selected one, Ctrl+K focuses the
  field even in a background tab (a timer, not only a frame callback — that was the
  "Ctrl+K does nothing mid-turn"), and one-letter words are never bolded.
- **chat**: the model's context now outlives a restart. The runtime's session store —
  the context itself: session state, rewind points, plan, tool history — defaulted to the
  **temp dir** while the transcript lived in app data, so any temp cleanup deleted the
  context behind a history still on screen and `resume` had nothing to restore. It lives
  beside `chat.db` now, with a one-time move of an existing temp home.
- **chat**: renaming a thread no longer overwrites the runtime session *name*, which is
  the key `resume` looks up — a renamed thread had silently become unresumable.
- **chat**: the context panel keeps the last snapshot per conversation and serves it as
  `stale: true` when the live attribution is unavailable, instead of showing zeros.
- **proxy**: `WEBRAIN_PROXIES` now reaches every HTTP fetch. The pool was consulted only
  where a caller resolved it (`http_search` and nine handlers that called
  `.or_else(next_proxy)`), while the shared agent still fell back to a direct connection —
  so `read`, `batch op=scrape|read` and engine-level fetches went out from the host IP
  even with the pool set. The fallback now lives in the agent, per request, so a batch
  spreads across exits; an explicit `proxy` still wins and never rotates.
- **mcp**: `webrain_batch op=pdf` was advertised in the op list and never dispatched — it
  fell through to `fetch`, so a PDF URL answered `status: ok` with zero text. The op is
  gone; PDFs are `webrain_pdf`.
- **webrain_batch**: every row now reports the document it actually read (`title`), so a
  challenge, consent or 404 page is visible instead of looking like "no matches".
- **webrain read**: the first 401/403 ends the `.md` retry loop, instead of spending
  three blocked requests on a URL that is refusing the client.

## v0.19.0

<p className="text-[#888] text-sm">2026-11-21 — the chat page becomes something you can read a table in, the browser fixes it needed, and a recording of it in the README</p>

### Added

- **chat**: a **reply rendering** switch (`markdown` / `html`) for models that answer
  in HTML, with the same sanitiser on both paths; a stream that re-renders only its
  last block, so each new word fades in without flickering the paragraph above it;
  eased scroll-follow; and a container tone under a picture before it loads.
- **chat**: in `html` mode the turn now names the class vocabulary the stylesheet
  owns (`section.card`, `div.grid`, `div.stat`, `span.pill`, `progress`, `details`,
  `figure`, `kbd`, `mark`, …) **and the shape to reach for unasked** — a short answer
  is `<p>`, comparable items are `div.grid > section.card`, a comparison is a
  `<table>` — so a dashboard no longer needs to be requested in the prompt, in the
  page's own colours, and still with `<script>`, `<style>` and `style=""` dropped by
  name. Fixed cost: 877 chars (~220 tokens) per turn.
- **chat**: the follow-up chips work for any kind of chat — evidence first (the
  failed tool, two sources to compare, a capture, a written file, code or length in
  the answer), then a floor true of any finished answer, so a plain question still
  ends with three things to press. Reasoning text is escaped before rendering, so a
  model that writes `<p>` while thinking about HTML no longer loses the word.
- **chat**: the right rail totals the conversation — turns, tokens, steps, sources
  and cost — above the per-turn ledger, with money reported as a lower bound when a
  turn ran on a model that publishes no price.
- **chat**: the render vocabulary and the `<suggest>` contract are **standing
  instructions** now, applied by the runtime to every turn, instead of prompt text
  re-sent each time (~1.2 kB saved per answer); flipping the switch is one patched
  setting, and the Runtime tab's instructions field still shows only what you typed.
- **chat**: the three follow-up chips are written by the model that answered — it
  ends the reply with a machine-readable `<suggest>` tail that the page lifts out and
  renders as buttons — with the derived list kept as the fallback; and the usage line
  under an answer now ends with the turn's **step count** and **duration**, scaled
  from `240ms` to `1y 1mo` instead of always seconds.
- **chat**: tool rows read as sentences — `Searched the web for “…”`,
  `Ran curl -s -m 5 …`, `Read el.aegeanair.com`, `Edited src/App.svelte` — derived
  on the page from the tool's name and arguments, with the wire name kept beside
  them because that is what a re-run sends back. The live line uses the same
  words, and a turn that had failures summarises them once at the end.
- **batch (memory contract)**: a batch sizes itself from the machine and says so —
  `tabs_allowed` (free RAM ÷ ~56 MB per tab, capped by cores ×2), `cost_multiplier`
  (`3` for `screenshot`/`pixel`/`pdf`, so a bitmap tab buys a third of the tabs),
  `mem_total_mb`, `mem_available_mb` and `throttled_by_memory`. A slow run now has a
  stated reason instead of looking like a slow site.
- **batch (pressure valve)**: free memory below 12% of total retires the workers past
  the halfway mark — checked before they claim a URL, so no row is lost — and they
  stay retired for the batch. Below one tab's cost at admission the batch refuses with
  a named error per URL instead of starting and dying halfway; `WEBRAIN_MAX_TABS`
  skips the refusal, because an explicit number is a decision, not an estimate.
- **mcp (retry)**: a read-only call that finds a latched dead socket reconnects and
  runs once, so a browser restart no longer costs the caller the whole turn. Mutating
  tools are deliberately not retried — a click that landed with its reply lost must
  not run twice. Counted as `mcp.retries`.
- **traces**: `handle_rpc` and `tools::call_tool` are instrumented (`RUST_LOG=debug`),
  the second with the folded tool name, so `observe{what:screenshot}` shows up as
  `webrain_screenshot`.
- **screenshot (`b64`)**: `b64: false` returns the file path only. The base64 stays the
  default because it is what the MCP `image` block is built from.
- **extraction (autoschema)**: an empty candidate list now says why —
  `diagnosis: {reason, min_occurrences, best_repeat, containers}` with
  `no_candidate_containers`, `too_few_repeats` or `no_fields`, so `[]` is
  distinguishable from a selector miss.
- **stats**: `webrain_stats` reports `cdp_latency` per CDP command (`n`, `avg_ms`,
  `max_ms`) with an `other` bucket, plus `mcp.calls` / `mcp.errors` / `mcp.retries`.
- **capabilities**: every `navigate` reply and the batch `stats` carry a `capabilities`
  object (`transport`, `parallel_tabs`, `single_target`, `stealth`) filled from the
  probe the batch path already runs. `null` means "not probed yet", which is not
  `false`.
- **chat**: `/rewind` walks the conversation back to an earlier turn — and, when
  the runtime captured them, the files those turns changed. `undo` only puts back
  the last file and `fork` only copies the transcript. The files a rewind would
  restore are listed before anything is written. `enable_file_change_tracking` is
  now set for `--serve`, which is what makes file restore possible at all.
- **chat**: the session mode is a **runtime switch**, not a sentence on the front
  of the prompt — `interactive` / `plan` / `autopilot` goes to `session.mode.set`,
  so `plan` is the mode the agent operates in.
- **chat**: two read-only commands — `/instructions` (the instruction files the
  model was given, in merge order) and `/quota` (account credits, null on a key of
  your own rather than an empty meter).
- **chat**: a queued prompt can be **corrected or dropped**, not just promoted.
  One you can send but not edit is one you retype, which starts a second turn.
- **chat**: a message that **did not come from this composer** now draws a bubble
  — an autopilot continuation, a steering note from another client — instead of
  leaving an answer to a question nobody could see. `session.shutdown` prints the
  session's bill (tokens, cost per model, files changed) rather than one line.
- **chat**: reasoning is **filed with the step it produced** rather than pooled at
  the end of the turn — a folded row above the tool call or answer it explains,
  which is the order it happened in and survives into a saved conversation. The
  live panel then only shows the step that is running.
- **chat**: a tool server that has died now says so. The runtime's MCP-health
  events feed a per-server map, and anything that is not `connected` raises a
  banner naming the server and its error with a **reconnect** button — before,
  a dead server looked like a model that had forgotten how to scrape.
- **chat**: facts the agent wants to keep **across sessions** are now their own
  approval card — the fact quoted, its subject and citations, Deny / Remember /
  Always remember — instead of an anonymous tool approval with no arguments.
- **chat**: opening a saved conversation now paints the same **120-row window** the
  live transcript does, with "show earlier" to grow it — it used to paint the whole
  thread at once, at one markdown parse, one shape read and one link preview per
  row (a 300-row scrape measured 120 rows / 40 parses / 1714 DOM nodes to open,
  against 300 rows / ~100 parses / ~3900 nodes before). The rows are keyed by id,
  so growing the window moves them instead of re-creating them.
- **chat**: pasting a long block into the composer now leaves a **chip** above the
  field instead of a receipt line carrying your temp path. The path is still what
  the agent is told — the line is composed at send time from the chip list, so the
  field only ever holds what you typed — and the chips survive a reload.
- **chat**: a turn can no longer leak between conversations, and history keeps the
  evidence. Every event carries the conversation it belongs to, so a tab drops the
  frames of a turn running somewhere else; the rail marks the conversation the
  turn is actually running in, and a fresh tab opens on what the live conversation
  already said instead of an empty pane. A new `transcript` table stores the rows
  the page drew — tool calls with their arguments and results, the steps strip,
  the notes — so reopening a scrape shows the evidence rather than prose that
  mentions it. Source chips also gained the page's own preview (`og:title`,
  `og:image`, description), fetched server-side because a browser cannot read
  another origin's `<head>`; `#tool` and `@skill` are tinted where they are typed;
  the tools dialog gained a per-tool `ask` / `always` approval policy; and a turn's
  steps strip now sits above the answer it explains instead of under the sources.
- **chat**: the page can now change a **live session** instead of rebuilding it.
  A tool row grew **edit & re-run** — the arguments become a textarea, the call is
  re-sent through the runtime's own invocation pipeline with no model turn, and the
  answer lands as a new row so the original call stays visible. The Runtime tab
  gained a **permission mode** control (`ask me` / `assisted` / `allow all`), which
  is the policy the *runtime* enforces, not the page's own approvals. The `/skills`
  and `/mcp` notes became **togglable cards**, so a stopped MCP server — the reason
  a turn suddenly has no tools — can be restarted without losing the session. A
  **queue rail** above the composer shows prompts waiting behind the running turn
  and can promote one, so a queued message cannot be mistaken for a lost one. An
  open approval also survives a page reload: the server hands the pending cards
  back on boot instead of leaving the turn waiting for an answer nobody can give.
  And saving Runtime settings no longer restarts the session for the three fields a
  live session can absorb, which was costing a prompt cache to reword an
  instruction.
- **chat**: conversations are **addressable**. A `new chat` button mints an id
  server-side and puts it in the address bar, so `/<id>` *is* the conversation:
  a reload opens that thread instead of a 404, and the id survives bookmarks and
  pasted links. `GET /sessions` now reports `busy`, so a reloaded page re-attaches
  to a turn that is still running instead of looking idle. The transcript paints a
  window of 120 rows with "show earlier" rather than every row of a long turn,
  which is what keeps a big scrape from freezing the tab. Code cards normalise
  their language (`rs`→`rust`, `py`→`python`, `sh`/`bash`/`ps1`→`shell`, …) and
  finally line up indentation without a highlighter; source chips also stop
  repeating the same page under `#fragment` and trailing-slash spellings.
- **chat**: four SDK surfaces we had left on the table. Big tool output now
  spills to `<cwd>/.webrain/tool-output` rather than the OS temp dir, which our
  own path fence refused — so a >50 KB extraction no longer forces a re-scrape.
  The self-attached MCP server gets a 600 s call timeout, because a real crawl
  outlives the runtime's default and was reported as a failed tool. Standing
  instructions are a Runtime-tab box applied by the runtime, not pasted onto
  every prompt. And six events that already reached the page are handled:
  `assistant.intent` and `assistant.tool_call_delta` (the live step says what the
  agent is doing instead of "working"), `assistant.turn_retry`,
  `agent.interrupted`, `session.title_changed`, and `session.context_cleared` /
  `session.context_changed`.
- **chat**: approvals moved **into the transcript**. A permission is a card under
  the tool call that asked for it — tool, server, read-only or not, and the exact
  arguments — with *Deny* / *Approve once* / *Always allow 'tool'*. That last
  button used to be keyed on the runtime's `kind`, so "Always allow tool" granted
  every tool there was; it now covers one tool on one server, and says which. The
  card keeps its verdict, and Escape no longer denies.
- **chat**: the **thinking panel opens itself** when reasoning arrives and stays
  open through every tool call in the turn, instead of collapsing after each one.
  Reasoning is kept for the whole turn and split into steps, so a three-call turn
  reads as three thoughts; a manual collapse still wins until the next turn.
- **chat**: the session itself carries a reasoning effort, so a **delegated
  worker** reasons at the level you picked instead of at the runtime's default —
  the composer's effort chip only binds a turn, and a spawned sub-agent has no
  turn of its own to inherit from. It lives in `settings.json` and the Runtime tab
  as a segmented control, unset meaning "the runtime decides". Sub-agent streaming
  is on too, so a worker's steps appear while it works instead of the row sitting
  silent until it finishes.
- **chat**: three read-only routes say what the session actually has, each with a
  `/` command. `GET /context` returns the runtime's own accounting
  (`10875/1000000 tokens · system 479`) with per-category attribution — which is
  the only honest answer to "why did cost change?"; `GET /mcp` proves the attached
  MCP server is *answering* rather than merely listed; `GET /skills` lists
  installed skills beside the ones the agent actually used. `/context` also names
  the five heaviest messages, so "why is my context full" has an answer at the
  message, not only the category.
- **chat**: eleven runtime events the page was dropping are now shown —
  `session.warning`/`session.info`/`system.notification` (a runtime warning was
  invisible), `tool.execution_progress` (a slow scrape looked hung),
  `session.compaction_*` and `session.truncation` (history was being rewritten
  silently), `session.plan_changed`, `session.model_change`/`mode_changed`,
  `abort`, `permission.completed`, and `tool_search.activated`. Sub-agent rows
  carry their duration, tokens and tool calls.
- **chat**: prompt-cache behaviour is visible — the CLI usage block and the page's
  topbar both show the cached share (measured at **84%** on deepseek with the
  3 186-token prefix), and the runtime's `prompt_cache_break` event prints how much
  prefix was lost and how much survived, which is the only signal that explains a
  turn suddenly costing full price.
- **chat**: turns are 6× cheaper in context — **3 186** input tokens instead of
  **19 753**. The runtime's built-ins are no longer allowlisted with `builtin:*`
  (6 972 tokens of schemas for tools `chat_tools` already covers), and the 18
  `webrain_*` MCP schemas (9 820 tokens) are deferred behind the SDK's
  `tool_search`, with the threshold lowered to 1 because the runtime default of 30
  sits above our tool count and defers nothing. Tool use still works: the model
  searches for a tool, loads it, and calls it.
- **chat**: a new **Runtime** settings tab drives the switches a page cannot
  express as prompt text — remember across conversations, keep a session store,
  allow sub-agents, completion budget, turn timeout — persisted to
  `settings.json` beside the chat database and exposed as `GET/POST /settings`.
  Defaults are the constants the session used before, and the server answers
  `{"restart":true}` when a save needs a rebuilt session rather than pretending a
  checkbox reached a live one.
- **chat**: `GET /todos` returns the agent's todo rows and dependency edges from
  the session SQL database, and the `/` menu gains a `todos` command that prints
  them. `POST /fleet` hands the runtime an objective to dispatch sub-agents,
  refusing when delegating is switched off.
- **chat**: `compact_at` sets where history is rewritten (30–80% of the window;
  the blocking threshold follows 15 points later, so the default reproduces the
  runtime's own 0.80/0.95 pair). A 1-token budget and a 1-second timeout are now
  clamped to 64 and 30 instead of being stored as settings that cannot work.
- **chat**: a delegated sub-agent now receives the workspace's `AGENTS.md`
  (`on_subagent_start`), which `on_session_start` never reached, and
  `session.todos_changed` prints the todo list as it moves.
- **chat**: `GET /tasks` lists the agents a session is running and
  `POST /agents` messages one of them mid-flight — the parent-to-child half of
  delegation that `/fleet` only started. The list is passed through untyped, as
  the runtime sends it. `fleet` with no objective now runs the last thing asked,
  and `agents`, `fleet` and `todos` are all in the `/` menu.
- **chat**: a topbar chip shows how many sub-agents are running and lists each
  one's name, type and execution mode on click, driven by the `subagent.started` /
  `completed` / `failed` lifecycle events — otherwise a delegated worker is
  invisible while it works. It cannot address one, because the payload carries no
  task id.
- **chat**: `edit_file`/`write_file` keep the previous state of the file, and
  `/undo` (or `POST /undo`) puts it back — restoring the bytes, or removing a
  file the write created. The tool row already showed the diff; this is the half
  a diff cannot do. Twenty changes deep, and process-scoped: an undo for what
  this chat just did, not a checkpoint system.
- **chat**: a conversation opened from the menu is continued, not replayed.
  Opening it moves the live conversation, the next turn replaces the runtime
  session and carries the stored transcript (`[earlier in this conversation]`,
  6 KB of whole messages), and both sides of the turn land in the conversation
  the page shows instead of a hidden new one. If the restart fails the running
  session stays and the failure is reported, so the chat still answers.
- **chat**: plan mode leaves a plan behind. The answer to a plan-mode turn is
  written to the runtime's plan file and read into every later prompt as
  `[the plan on file]`, so "do it" does not need the plan restated. `GET /plan`
  and `POST /plan {"content"}` expose it to the page and to scripts; a failed
  save reports on the event bus instead of losing the plan silently. The page
  shows a plan chip beside the theme toggle when a plan exists, so what the next
  turn will be told is visible.
- **chat**: a `preToolUse` fence over the runtime's own tools. `bash` is denied
  outright — it has no path to inspect and the process's whole filesystem as its
  reach — and the path-taking built-ins are refused outside the chat's directory,
  so approving a permission prompt can no longer move the boundary. The fenced
  `run_shell` / `terminal` are named in the denial.
- **chat**: `AGENTS.md` (else `.github/copilot-instructions.md`) from the starting
  directory is injected at session start, capped at 4 KiB.
- **chat**: `edit_file` now reports the change (`- old` / `+ new`) and the line.
- **core**: CapSolver alongside 2captcha — JSON `createTask` → `getTaskResult`
  poll, `ReCaptchaV2Task` when a proxy is given (`…ProxyLess` otherwise), vendor
  errors surfaced verbatim, `CAPSOLVER_API_KEY` first and `WEBRAIN_2CAPTCHA_KEY`
  as the fallback.

- **captcha**: the paid reCAPTCHA-v2 solver is reachable from both surfaces —
  `webrain_session {op:"captcha", sitekey, page_url, data_s}` and
  `webrain captcha --sitekey … --url …`. Both pick the provider and return
  `{provider, token}`; with no key they name both variables. They buy a token —
  reading the sitekey and injecting it stays with `eval`, and hCaptcha /
  Turnstile / drag challenges stay on the vision flow.

- **crawl**: `dedupe_pages` on `webrain_crawl mode=spider` keeps the first page
  per visible-text hash and reports `duplicates` — a forty-page listing costs one
  row instead of forty. Off by default, because it removes rows; error pages are
  never dropped.

### Changed

- **build**: `webrain-cli` inherits the workspace `rust-version` (1.94) like the
  other two crates, so the package that carries the `chat` feature declares the
  MSRV the SDK forces.
- **serp**: `SERPAPI_API_KEY` now covers every engine serpapi serves — google,
  bing, duckduckgo, yahoo, baidu, yandex — not google alone, so
  `--engine yahoo --limit 12` answers from serpapi's yahoo set instead of being
  handed google's rows. Parameters follow serpapi's own docs, per engine:
  google `q`/`hl`/`gl`, bing `q`/`cc`/`mkt`, duckduckgo `q`/`kl`/`m`,
  yahoo **`p`**/`vc`/`vl`, baidu `q`/`rn`, yandex **`text`**/`lang`/`p`. Sending
  google's `hl`/`gl` to all six was silently ignored, so `--region` did nothing
  outside google, and `--safe` now maps to each engine's own spelling. `auto`'s
  deep fill walks every serpapi engine (google first) and stops as soon as the
  limit is met, instead of google alone — one ~9-row google set could not fill a
  40-result request. Brave is unchanged — serpapi has no brave engine.
- **serp**: a refused serpapi key is reported instead of swallowed — `skipped`
  now carries `google (serpapi: HTTP 401: Invalid API key…)` rather than a bare
  `google (serpapi)`, which was indistinguishable from "this engine had
  nothing", and `auto`'s fill stops after the first refusal.
- **captcha**: the 2captcha key answers to two spellings —
  `WEBRAIN_2CAPTCHA_KEY` and `TWOCAPTCHA_API_KEY`. `CAPSOLVER_API_KEY` still
  wins when both vendors are configured (cheaper + faster per solve) and the
  reply's `provider` names the one that ran. `2CAPTCHA_API_KEY` is deliberately
  not read — a name starting with a digit cannot be exported in a POSIX shell.
- **crawl (engines)**: the spider dedupes its frontier on path + sorted query
  params, ignoring the anchor fragment, so `?b=2&a=1#top` and `?a=1&b=2` are one
  page. The visited set was exact-string before, so every facet permutation was a
  separate fetch. A `#/` hash route is kept — it is a real page, not an anchor.
- **crawl (engines)**: the politeness gate is keyed per host. `delay_ms` is the
  gap between request starts (`500` = 2 req/s), so two domains used to split
  those 2 and now each gets its own 2.
- **serp**: bing is fetched as HTML at every offset; `format=rss` is gone. The
  RSS feed was a second document shape (XML `<item>`, its own parser and entity
  decoding) that also ignores `count`/`first` and empties when a market is
  pinned. `parse_bing_rss` and its helpers are deleted; `--limit 10` measures 10
  rows with `source: bing`.
- **docs**: the Chat section of the README now carries a 13-frame recording of one
  turn (`docs/images/chat-turn.gif` — the prompt, the answer streaming, the closing
  `… · 0 steps · 6.2s` line, the three follow-up chips) plus a still of an `html`-mode

### Fixed

- **`wait_selectors`** was ignored whenever `cdp_urls` was set (the grouping lived
  inside the `cdp_urls.is_empty()` branch), so a site that hydrates after
  `readyState: complete` came back as shells. Probed: plural returned in 492 ms,
  singular took 12.6 s; after the fix, 13.0 s and the expected rows.
- **`wss://` CDP endpoints** connected at all: `tokio-tungstenite` had no TLS
  connector, so every hosted endpoint — Lightpanda Cloud included — failed despite
  `resolve_ws` passing `wss://` through. `rustls-tls-webpki-roots` now ships the
  roots in the binary.
- **`webrain_batch` with `cdp_urls`** returns rows in **input order** (they were
  appended per backend, so `results[i].url` did not match `urls[i]`), runs the
  per-backend batches **concurrently** (the loop awaited each in turn, so N
  backends bought zero throughput), and counts the tab budget across backends
  (`per_backend_concurrency` is clamped to `tab_budget / backends`).
- **batch now uses a fixed tab pool** — one tab per worker draining a shared
  queue instead of an attach + init per URL, so live tabs are bounded by
  `concurrency` however long the list is; `stats` reports
  `requested/effective_concurrency`, `single_target` and `ms_wall`, because
  lightpanda silently collapses to one tab and `ms_total` cannot show parallelism.
- **a killed browser no longer wedges the server** — after a kill the error is
  `CDP write failed: channel closed`, which shares no phrase with
  `connection closed`, so `is_connection_error` never dropped the cached backend
  and every later call replayed the dead socket until the MCP process restarted.
- **bing returned zero results on every query** and had for a while, silently,
  because `auto` just merged duckduckgo and moved on: its HTML SERP is
  JS-rendered for programmatic clients. Page 0 now uses the RSS form Bing
  advertises (which deliberately omits `mkt`/`cc` — both empty the feed), so
  `--limit 20` reports `bing ok(10)` where it used to report `bing empty(0)`.
- **google returned zero results from a perfectly good page** — the target is now
  an opaque `/goto?url=CAES…` token, so every row resolved to `google.com` and was
  discarded as an internal link. The URL is recovered from the `<cite>` line
  (9 of 10 organic rows); a cite holding metadata yields nothing rather than a
  fabricated link.
- **`webrain_scrape` can parse instead of probe** — the browserless fetch capped
  every body at 3000 chars, so 3 KB of `<head>` was all a caller ever saw.
  `max_chars` / `full` lift it and the reply reports the true `bytes` plus
  `truncated`; a Sklavenitis page is 427 KB in 266 ms, 3–8× faster than the same
  page in a tab.
- **`serp --http`** — never touch a browser. `--engine bing --limit 50` used to
  guest-launch Chrome for 26 s and return 10 results; with `--http` the same 10
  arrive in 0.3 s.
- **Chrome's own throttling, not the SERP code, made browser searches slow by
  5–30×** — an automated window behind the editor reads
  `document.visibilityState === "hidden"` and one google page took 16–22 s against
  3.4 s visible. `webrain launch` now passes
  `--disable-features=CalculateNativeWinOcclusion` plus the backgrounding flags.
- **`auto` asked browser engines for the full limit**, so a deep request became 8
  google pages and the 20 s browser cap threw the render away; the browser stage
  is a diversity top-up and now asks for exactly one page.
- **`consent_button` clicked the last button inside any dialog** when no
  accept/reject label matched — Google's own "About this result" panel is a
  dialog, so every run opened a side panel over a good results page. The blind
  fallback is deleted.
- **docs** — obscura does have a paint engine (`fetch -s out.png` wrote a 63 KB
  PNG); what fails on a data-driven SPA is **boot, not paint**, and the cause is
  that obscura gives every element one shared `Element` prototype, so a polyfill
  for `HTMLTemplateElement.firstChild` patches `firstChild` for all elements and
  React never hydrates. Probe before trusting any engine on an SPA:
  `HTMLTemplateElement.prototype === Element.prototype` must be `false`. The MCP
  relaunch recipe is written down too, including the trap that `webrain serp` sets

## v0.8.0

<p className="text-[#888] text-sm">August 27, 2026</p>

### Security

- **engine archives are extracted behind a zip-slip guard** — absolute paths,
  `..` traversal and Windows drive-prefixed entries are rejected, exec bits are
  preserved, and each download chunk has a timeout.
- **`lightpanda` / `obscura` CDP servers bind to `127.0.0.1`** (they were on
  `0.0.0.0`, exposing unauthenticated browser control on the LAN).
- **2captcha credentials leave the URL** — the submit is a form POST, so the key
  and proxy credentials stop appearing in access logs; the proxy is validated
  up-front instead of silently dropped from a paid solve.
- **vault hardening** — `vault.key` is created exclusively with `0600`,
  unreadable keys error instead of reading as "empty", writes are atomic, and
  read-modify-write is serialized so concurrent mutations cannot drop an entry.
- **installers verify the binary** against the release's `checksums.txt` and
  fail closed; downloads go to a temp file and move into place atomically, and
  HTML-200 downloads are rejected by magic bytes.
- **HTTP transport caps the request body** at 16 MiB; search queries are
  percent-encoded (`&`/`#`/`%` could inject parameters or truncate); third-party
  Actions are pinned to full commit SHAs.

### Added

- **`batch op=markdown`** — full page HTML → Markdown via pure-Rust `htmd`,
  past the 3000-char `innerText` cap, with optional `query` + `top_k` BM25
  pruning (zero LLM).
- **`per_engine` SERP breakdown** — `[{engine, status: ok|empty|skipped, count}]`
  so a reply says which engines contributed and which were skipped.

### Fixed

- **`auto` is relevance-filtered** — results sharing no significant query token
  are dropped at the source, so a junk page from a flagged IP can no longer fill
  `limit` ahead of duckduckgo's real results; a fallback reply now carries
  `source` (the actual provider), so substituted results are never mislabelled.
- **consent dismissal can no longer click a search result** — Google's app-shell
  `#yDmH0d` was in the consent-gate selector and the last-button fallback then
  clicked a result link. The gate now requires a real dialog/banner container.
- **google's URL is a real-browser URL** again — `num` and `lr` made it answer an
  empty page on automated sessions, and that soft-block is now detected as a
  wall so the retry loop fails fast instead of burning four attempts.
- **bing** routes through the browser (`first=1,11,21…`) and falls back to plain
  HTTP when no Chrome can be launched; its browser path makes one attempt, so a
  no-result query falls back in ~6 s instead of ~30 s.
- **serp reliability** — an HTTP engine that parses to zero on a 2xx page is
  retried before being called broken, google pagination budgets ~7 results per
  page (carousels and AI overviews crowd the SERP), `brave` left
  `HTTP_ENGINES`, and `limit` went 50 → **100**.
- **CDP** — consistent `active → tabs` lock order (a deadlock inversion), a 30 s
  response timeout, a serialized first attach, unique per-element selectors so a
  bare `input` cannot set files on the wrong node, and the network block list is
  re-applied on every navigation.
- **`detect_antibot` requires two corroborating markers** for generic phrases,
  so a support article mentioning "access denied" is no longer read as a block;
  `crippled` is gated on element-extraction success.
- **`ELEMENTS_JS` / `LINKS_JS` moved onto the `BrowserBackend` trait**, so any
  backend supplies its own extraction script instead of the shared snapshot path
  reaching into `backends::cdp`.
- **`serp`'s stealth-off is a per-backend flag**, not
  `std::env::set_var("WEBRAIN_NO_STEALTH")` from a concurrent handler — an
  edition-2024 data race that disabled stealth for every session in the process.
- **long-running work left the executor** — `webrain_watch`, `http_fetch`,
  `pdf_images`, `vault::list`, robots.txt fetch, vision's provider chain and
  `index_current_page` all run off-thread, so a slow call no longer ties up a
  tokio worker (the watch session table is capped at 64).
- **`vault`/`login`** — a TOTP seed with non-zero trailing bits is refused, and a
  missing captcha token bails with `waiting_for_human` instead of submitting a
  guaranteed-403 empty one.
- **docker** — the release build no longer loses the binary (the target cache
  mount never reaches the image layer), and the cache is keyed by `$TARGETARCH`.
- **docs** — landing coverflow order, its no-JS fallback and the playground
  generation guard fixed; the SERP showcase made capability-honest (duckduckgo
  over HTTP, "2 browserless by default"), tool counts corrected to 16, and a
  docs-orphan check added to CI.

## v0.1.0

### New Features

  `webrain-core` / `webrain-mcp` / `webrain-cli`; MIT license; CI + release +
  changelog-enforce workflows.

  for Testing (and `--engine obscura`); `webrain lightpanda` / `webrain
